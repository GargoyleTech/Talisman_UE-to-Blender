# FF7R Rebirth Tools

One Blender add-on containing the retained FF7R tools:

- **UMAP importers:** `File > Import > FF7R Rebirth` includes separate Massive Environment entries for loose `.umap`/`.ubulk` files and maps mounted directly from Rebirth's packages. The package UMAP browser imports StaticMesh actors from mounted game data, sharing one Blender mesh datablock across repeated actors. **Experimental: Nearby MEC Terrain** checks each top-level map root in the selected East, West, or North continent and selects levels from its `EndStreamingVolume` brushes around a Blender-space radius. It imports those levels' MEC data at its coarsest LoD with one untextured material at continent-local coordinates by default; the continent's `0001-WORLD` origin is an optional placement offset. It is intended as quick rough context around an already-imported cutscene.
- **StaticMesh importer:** `File > Import > FF7R Rebirth > Static Mesh (Rebirth Packages)` accepts a mounted `.uasset` virtual path. It supports the update's flattened/meshlet layout and falls back to the earlier conventional layout, including their respective packed-normal formats. It imports geometry, custom normals and tangents, all UV channels, vertex colors, material slots, and package-path metadata. RMI_Surface material instances are built as their researched variant and their texture parameters are packed automatically; Unreal color parameters are represented by RGB constant nodes instead of image-texture nodes. This currently applies only to direct package StaticMesh imports and package-backed UMAP StaticMesh actors. The dialog is prefilled with `End/Content/Environment/Machine/Model/Machine_MagicStore_01A.uasset` as the verified reference asset.
- **Remake mesh importers:** Remake StaticMesh, SkeletalMesh, and UMAP imports build a basic Principled Blender material from the cooked Color, Metallic/Roughness/Variant, Normal, LDREmissive, and Occlusion texture parameters. Metallic/Roughness/Variant maps red to Metallic and green to Roughness; Variant is retained but not interpreted. Normal maps use DirectX convention. Texture extraction is best-effort because some Remake DDS payloads cannot currently be decoded. Remake's cooked properties still require a compatible mapping file even though the title is based on UE 4.18.
- **Crisis Core StaticMesh importer:** `File > Import > FF7R Rebirth > Static mesh (Crisis Core)` indexes actual `UStaticMesh` assets from Reunion's `AssetRegistry.bin`, then imports conventional UE 4.27 geometry, normals, tangents, UV channels, vertex colors, named material sections, and package metadata. Materials remain placeholders because Crisis Core has its own material setup.
- **Remake and Crisis Core SkeletalMesh importers:** `File > Import > FF7R Rebirth > Skeletal mesh (Remake)` and `Skeletal mesh (Crisis Core)` index conventional `USkeletalMesh` assets alongside their static meshes. They preserve normals, tangents, UVs, material sections, per-vertex skin weights, and the linked Skeleton path. By default, each import builds and binds a new armature from that linked Skeleton; alternatively, it can bind the mesh to the active matching armature. Remake uses the basic material reconstruction described above; Crisis Core has its own material subset.
- **Remake and Crisis Core UMAP importers:** `File > Import > FF7R Rebirth > UMAP (Remake)` and `UMAP (Crisis Core)` index mounted map packages and create their ordinary UE component placements. They reuse shared StaticMesh/SkeletalMesh datablocks for repeated assets, construct linked skeletons where available, and import point and spot light transforms and settings. Rebirth’s proprietary Massive Environment terrain route remains separate.
- **KineDriver importer:** select an armature, then use `File > Import > FF7R Retrilogy > Rebirth > KineDriver JSON` for loose files or `KineDriver` for a Rebirth package. The same menu's **Remake** section provides `KineDriver` for a configured Remake install and mapping file. Remake's older connector records are adapted into the shared KDI graph, including keyed link curves and aim/up direction targets. Each import audits the selected KDI internally and builds the driver layer in one operation. The audit graph is saved in the `.blend`; `Object > Retrilogy tools > KDI: Visualize Driver Graph` therefore opens it without asking for the KDI again. In Pose Mode, right-click a KDI-driven bone and choose **KDI: Focus Selected Bone in Graph** to show just the subgraph that drives it in any open node editor.
- **Animation importer (first pass):** select a package-imported armature, then use `Object > Retrilogy tools > Apply Rebirth Animation`. It records the source Skeleton on newly imported package armatures (and can infer it from a bound package SkeletalMesh in older scenes), searches compatible `AnimSequence` assets by Skeleton, and creates a named Blender Action. Source frame timing is converted to the current scene frame rate; UE local transforms retain the package rig's Blender bone-roll convention.
- **Opposite-face fix and KDI removal:** `Object > Retrilogy tools`.

When building the KineDriver layer from loose JSON, the file browser includes independent translation and scale mappings and defaults to `X → X, Y → Z, Z → Y`. Package-built Remake and Rebirth armatures carry an intentional +90-degree display-bone roll; their package KDI importers detect that profile and automatically use `X → Y, Y → Z, Z → X` together with the matching rotation-frame conversion.

Implementation is split by responsibility: `core/` contains game-neutral bridge/profile and Blender infrastructure; `formats/ue_map/`, `formats/kdi/`, and `formats/mec/` contain reusable Unreal map, KineDriver, and Massive Environment handling; `games/<title>/` owns engine profiles and title-specific adapters; and `ui/` contains Blender preferences, menus, and small UI operators. The mature package importers and RMI material reconstruction currently live under `games/rebirth/`. `games/revelation/` is intentionally empty until that title can be profiled. `bridge/` contains the packaged CUE4Parse runtime used for direct game imports.

Direct package imports use CUE4Parse's package import map for texture-path resolution, so they do not depend on `formats/mec/texture_hashes.csv`. The CSV remains available only for loose exports that have no package metadata.

During batch UMAP imports, decoded package data is released as soon as each map's metadata and actor payload has been handed to Blender. The bridge compacts its large-object heap at that boundary and transparently restarts if more than 2 GiB remains allocated, preventing recursive imports from retaining every previously decoded map.

Package-backed Massive Environment imports can also read the referenced block-compressed textures directly from the mounted game data. DDS payloads retain their native BC/DXT encoding, are packed into Blender image datablocks, and leave no extracted texture library behind.

The package browser supports arbitrary multi-map batches with persistent checkboxes, folder navigation, full-path search, and select/invert/clear controls. It remembers the last browsed folder until Blender is closed. Package mounting, the StaticMesh cache, and the packed-image cache are shared across the complete batch. `AutoGenCollision` paths are omitted because they do not contain usable Massive Environment geometry.

## Installation

Install `ff7r_rebirth_tools.zip` through Blender's **Edit > Preferences > Add-ons > Install from Disk**, then enable **FF7R Rebirth Tools**.

Disable the separate FF7R UMAP importer and the old FF7R Actions add-on first. They register several of the same Blender operator identifiers, so running them together is not supported.

## KineDriver persistence

Keep this add-on enabled for any `.blend` file containing generated KineDriver drivers. The add-on restores the custom driver functions automatically when such a file is opened.

## Attribution

The UMAP importer payload is bundled from the supplied `ff7r_umap.zip`; its original author attribution is retained in the add-on metadata. The opposite-face operator preserves the behavior of the previous FF7R Actions tool.

## RMI_Surface source and provenance

The package StaticMesh RMI integration in `games/rebirth/materials/rmi_surface.py` loads its packaged builder, variant trimmer, and ground-truth table from `games/rebirth/materials/rmi_sources/`, with the sibling research checkout retained as a development fallback. The exact variant switch sets were generated from the current-build Renderer `MaterialInstance` exports' `StaticSwitchParameters`; the shader-method and RenderDoc provenance remain in that research project.

The bridge adds a mapping-independent MaterialInstance parameter read: CUE4Parse and the active `.usmap` provide the cooked `Parent`, texture, vector/color, and scalar parameter arrays. This lets the add-on assign packed DDS images to the appropriate RMI slots and convert matching Unreal vector/color parameters into Blender RGB constants without maintaining a second hand-authored parameter table.

The bundled `assets/Common_Eye_Player_NG_filtered.png` is a lossless 16-bit override for the exact shared game texture `/Game/Character/Common/Eye/Texture/Common_Eye_Player_NG`. It was derived from `O:/Blender/Rebirth DDS/Character/Common/Eye/Texture/Common_Eye_Player_NG.dds` with `tools/generate_common_eye_player_ng_override.py`. Two 3x3 binomial passes (equivalent to a 5x5 Gaussian) suppress BC5's 4x4 block boundaries before the eye shader amplifies them through cornea parallax; no other texture path uses the override.
